# 第10章 GitHub：コードを共有する

## この章のゴール

ブランチを作って変更をpushし、プルリクエストを作成・レビュー・マージできるようになります。

## 10-1 これまでの仕組みを図で振り返る

### やること

第6章でクローンしたときの仕組みを、改めて整理します。

### 考えてみよう

- 自分のパソコンの中にあるコード（**ローカル**）
- GitHub上にあるコード（**リモート**。`origin`という名前で登録されている）

この2つがどうつながっているか、`git clone`・`git commit`・（これから習う）`git push`が、それぞれどちらに対する操作かを、隣の人と確認してみましょう。

---

## 10-2 これまでのコミットをpushする

### やること

今までローカルに貯めてきたコミットを、GitHub（リモート）に送ります。

### コマンド

```
git push
```

初回は、GitHubへのログインを求める画面（認証）が出ることがあります。案内に従ってログインしてください。

### うまくいったときの結果

ターミナルに送信中のメッセージが表示され、完了する。

［スクショ ch10-1：初回push時の認証画面］

### うまくいかないとき

- 認証がうまくいかない場合、ブラウザでのログイン画面が別タブで開いていないか確認する

---

## 10-3 GitHubでコミット履歴を見る

### やること

自分のリポジトリのページで、pushした内容を確認します。

### 操作

自分のリポジトリを開き、「commits」のリンクをクリックする。

### うまくいったときの結果

これまでのコミットメッセージが、GitHub上でも一覧できる。

［スクショ ch10-2：GitHub上のコミット履歴］

---

## 10-4 ブランチを作り、画面の文言を変えてpushする

### やること

`main`ブランチに直接変更を加えるのではなく、専用の作業場所（ブランチ）を作ってから変更します。

### コマンド

```
git switch -c change-button-text
```

`public/index.html`の「追加」ボタンの文言を、好きな言葉（例：「タスクを追加する」）に変えて保存する。

```
git add .
git commit -m "追加ボタンの文言を変える"
git push -u origin change-button-text
```

### うまくいったときの結果

GitHub上に、`change-button-text`という新しいブランチができ、変更したコミットが入っている。

### うまくいかないとき

- `main`のまま作業してしまった場合、`git switch -c`を忘れていないか確認する

---

## 10-5 プルリクエスト（PR）を作る

### やること

「このブランチの変更を`main`に取り込んでほしい」という提案（プルリクエスト）を作ります。

### 操作

1. GitHubのリポジトリページを開くと、「Compare & pull request」というボタンが表示されるのでクリックする
2. 説明欄に「何を・なぜ」変えたかを書く
3. 「Create pull request」をクリックする

### うまくいったときの結果

PRのページができ、変更内容（差分）が表示される。

［スクショ ch10-3：PR作成画面（説明欄含む）］

---

## 10-6 ペアでレビューする

### やること

隣の人とお互いのPRのURLを交換し、レビューコメントを書き合います。

### 操作

相手のPRページで、変更された行にカーソルを合わせると出る「+」マークをクリックし、コメントを書いて「Start a review」→「Submit review」する。

### うまくいったときの結果

お互いのPRに、レビューコメントが1件以上付く。

［スクショ ch10-4：レビューコメントが付いたPR］

---

## 10-7 コメントを受けて修正する

### やること

もらったコメントを踏まえて、もう一度ファイルを修正し、同じブランチにpushします。

### コマンド

```
git add .
git commit -m "レビューを受けて文言を直す"
git push
```

### うまくいったときの結果

追加のコミットが、同じPRのページに反映される。

---

## 10-8 マージし、`main`を最新にする

### やること

問題なければ、PRをマージします。

### 操作

1. PRのページで「Merge pull request」→「Confirm merge」をクリックする
2. ターミナルで次を実行する

```
git switch main
git pull
```

### うまくいったときの結果

GitHub上で、PRが「Merged」の表示になる。

［スクショ ch10-5：マージ後の画面（Merged表示）］

ローカルの`main`にも、マージした内容が反映される。

### うまくいかないとき

- マージ後に`git pull`を忘れると、ローカルの`main`が古いままになる → 次にブランチを作るときに、混乱の元になるので必ず実行する

---

## この章の確認チェック

- PRを1件以上マージした
- 他の人のPRにコメントを付けた
