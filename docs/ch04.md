# 第4章 ターミナルとファイル、エラーの読み方

## この章のゴール

ターミナルでフォルダを移動し、Node.jsでJavaScriptファイルを実行できるようになります。エラーメッセージから、原因の場所を探せるようになります。

## 4-1 VS Codeのターミナルを開く

### やること

これまでも使ってきたターミナル（PowerShell）を、改めてしっかり使えるようにします。

### 操作

VS Codeのメニューから「Terminal」→「New Terminal」を選ぶ（すでに開いている場合はそのままでよい）。

### うまくいったときの結果

画面の下側に、文字を打ち込める黒っぽい画面（ターミナル）が表示される。`PS C:\...\>`のような表示（プロンプト）に続けて文字を入力できる。

---

## 4-2 フォルダを移動・作成するコマンド

### やること

ターミナルは「今どこのフォルダを見ているか（カレントディレクトリ）」を持っています。それを確認したり、移動したりするコマンドを覚えます。

### コマンド

```
pwd
```

今いるフォルダの場所（絶対パス：`C:\`から始まる、場所を一意に指し示す書き方）が表示される。

```
cd C:\dev
```

`C:\dev`フォルダに移動する（`cd`はchange directoryの略）。

```
ls
```

今いるフォルダの中身（ファイル・フォルダの一覧）が表示される。

```
mkdir js-basics
cd js-basics
```

`js-basics`という新しいフォルダを作り、そこに移動する。

### うまくいったときの結果

`pwd`を実行するたびに、今いる場所が変わっていくのが確認できる。

［スクショ ch04-1：pwd/ls/cd/mkdirの実行例］

### うまくいかないとき

- 「そのようなファイルまたはディレクトリはありません」のようなメッセージが出る場合、フォルダ名の綴りや、今いる場所（`pwd`で確認）を見直す

---

## 4-3 `hello.js`を作り、実行する

### やること

はじめてのJavaScriptファイルを、ブラウザではなくNode.jsで実行します。

### コード

`js-basics`フォルダの中に`hello.js`を作り、次の内容を書いて保存する。

```js
console.log('こんにちは、ターミナルの世界へ');
```

### コマンド

```
node hello.js
```

### うまくいったときの結果

```
こんにちは、ターミナルの世界へ
```

第3章まではブラウザのコンソールに表示していましたが、`node ファイル名`を使うと、ブラウザを使わずにターミナルの中だけでJavaScriptを実行できます。

### うまくいかないとき

- 「Cannot find module」のようなメッセージが出る場合、`ls`で`hello.js`が今いるフォルダにあるか確認する

---

## 4-4 わざと間違えたコードを実行し、エラーメッセージを読む

### やること

エラーメッセージには、原因を探すための手がかりが詰まっています。読み方を覚えます。

### コード

`broken.js`という新しいファイルを作り、次の内容を書いて保存する（`mesage`は`message`のスペルミスです。わざとこう書きます）。

```js
const greeting = 'おはよう';
console.log(mesage);
```

### コマンド

```
node broken.js
```

### うまくいったときの結果

次のようなメッセージが表示される。

```
C:\dev\js-basics\broken.js:2
console.log(mesage);
            ^

ReferenceError: mesage is not defined
    at Object.<anonymous> (C:\dev\js-basics\broken.js:2:13)
    ...
```

このメッセージには、3つの手がかりがあります。

1. **エラーの種類**：`ReferenceError`（存在しないものを参照した、という意味）
2. **メッセージ**：`mesage is not defined`（`mesage`は定義されていません）
3. **ファイル名と行番号**：`broken.js:2`（2行目）

この3つを読めば、「2行目で使っている`mesage`という名前が、どこにも定義されていない」と分かります。

### うまくいかないとき

エラーメッセージが長くて何を見ればいいか分からない場合、**一番上の数行**（ファイル名・行番号・エラーの種類とメッセージ）だけを見れば十分です。下に続く`at Object.<anonymous>...`のような部分（スタックトレース）は、今は読めなくて構いません。

## 4-5 エラーを直す練習問題

### やること

次の3つのファイルには、それぞれ別の種類の間違いがあります。エラーメッセージを読んで、自分で直してください。

### 練習問題1

```js
console.log('練習問題1');
console.log('閉じカッコを忘れた例';
```

### 練習問題2

```js
function sayHello() {
  console.log('こんにちは');
}
sayHelo();
```

### 練習問題3

```js
const message = 'こんにちは;
console.log(message);
```

### うまくいったときの結果

3つとも、エラーが出ずに実行できるようになる。

### うまくいかないとき

- 練習問題1：`SyntaxError: missing ) after argument list`と出ます。閉じカッコ`)`が足りているか数えてください
- 練習問題2：`ReferenceError: sayHelo is not defined`と出ます。関数を定義したときの名前（`sayHello`）と、呼び出すときの名前（`sayHelo`）の綴りを見比べてください
- 練習問題3：`SyntaxError: Invalid or unexpected token`と出ます。文字列を囲むクォート（`'`）がきちんと対で閉じているか確認してください

## 4-6 AIへの質問の仕方

### やること

これから先の章でも、AI（Claude Codeなど）に質問する場面が出てきます。良い質問の仕方を練習します。

### やってみよう

4-5の練習問題のどれか1つについて、次の4つを含めてAIに質問してみてください（すでに自分で直せていたら、もう一度壊してから質問してみましょう）。

1. 何をしようとしたか
2. どんな結果を期待していたか
3. 実際に何が起きたか（エラーメッセージ全文をコピーして貼り付ける）
4. ここまで自分で試したこと

### うまくいったときの結果

「エラーが出ました、直してください」だけの質問より、的確な回答が返ってくることを実感できる。

### 考えてみよう

なぜエラーメッセージを「全文」貼り付けることが大事なのでしょうか。4-4で学んだ「3つの手がかり」と関係があります。
