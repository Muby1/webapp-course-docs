# 第9章 データベース：データを保存する

## この章のゴール

NeonのPostgreSQLにタスクを保存し、サーバーを再起動してもデータが残ることを確認できるようになります。

## 9-1 Neonで「開発用」プロジェクトを作る

### やること

事前課題で作ったNeonのアカウントで、データベースのプロジェクトを作ります。

### 操作

1. https://console.neon.tech を開く
2. 「New Project」をクリックする
3. Project Name：例）`kantan-task-dev`
4. Postgres version・Region：講師の案内に従う
5. 「Create Project」をクリックする

### うまくいったときの結果

プロジェクトのダッシュボードが表示され、`neondb`というデータベースができている。

［スクショ ch09-1：Neon「開発用」プロジェクト作成画面］

## 9-2 SQLエディタでSELECT/INSERT/UPDATE/DELETEを試す

### やること

Neonのダッシュボードから、SQLを直接実行できる画面（SQLエディタ）を使ってみます。

### コード

SQLエディタで、次を1つずつ実行してみる。

```sql
CREATE TABLE sample (id SERIAL PRIMARY KEY, memo TEXT);
INSERT INTO sample (memo) VALUES ('はじめてのSQL');
SELECT * FROM sample;
UPDATE sample SET memo = '書き換えたメモ' WHERE id = 1;
DELETE FROM sample WHERE id = 1;
```

### うまくいったときの結果

`SELECT`のたびに、テーブルの中身が変化していく様子が確認できる。

［スクショ ch09-2：SQLエディタでの実行結果］

### 考えてみよう

`INSERT`・`SELECT`・`UPDATE`・`DELETE`の4つは、これまで画面で行ってきた「追加・一覧表示・完了切り替え・削除」と対応しています。

## 9-3 接続文字列を`.env`に書く

### やること

Neonのプロジェクトに接続するための文字列（接続文字列）を、`.env`ファイルに書きます。

### 操作

1. Neonのダッシュボードで「Connect」ボタンをクリックし、表示された接続文字列をコピーする
2. プロジェクトのフォルダで、`.env.example`をコピーして`.env`を作る

```
copy .env.example .env
```

3. `.env`を開き、`DATABASE_URL=`の後ろに、コピーした接続文字列を貼り付ける
4. 接続文字列の末尾が`?sslmode=require`になっている場合、`?sslmode=verify-full`に書き換える（`require`のままだと、起動のたびに警告メッセージが表示されるため）

### うまくいったときの結果

`git status`を実行しても、`.env`が変更ファイルの一覧に出てこない（`.gitignore`で管理対象外になっているため）。

### うまくいかないとき

- `.env`が`git status`に出てくる場合、`.gitignore`に`.env`が含まれているか確認する。**接続文字列をコミットしてしまわないよう、必ず確認してください**

## 9-4 サーバーを起動し、テーブルができたことを確認する

### やること

`npm run dev`でサーバーを起動すると、`db/schema.sql`が自動的に実行され、`tasks`テーブルが作られます。

### コマンド

```
npm run dev
```

### うまくいったときの結果

エラーなく起動する。Neonのダッシュボードに戻り、SQLエディタで次を実行すると、テーブルが存在することが確認できる。

```sql
SELECT * FROM tasks;
```

### うまくいかないとき

- 「DATABASE_URLが設定されていません」というメッセージが出る場合、`.env`ファイルが正しい場所（プロジェクトの一番上のフォルダ）にあるか確認する
- 接続エラーが出る場合、接続文字列を正しくコピーできているか確認する（1文字でも間違えると接続できません）

## 9-5 `db.js`の一覧取得・追加のSQLを完成させる

### やること

`src/db.js`を開くと、`getAllTasks`・`insertTask`という関数の中にTODOがあります。SQLの書き方は、9-2で試したものと同じです。プレースホルダー（`$1`など）を使うことで、値をそのままSQL文に埋め込まず、安全に渡せます（文字列をそのままつなげると、悪意のある文字列を送られたときに危険なSQLが実行されてしまう可能性があるため。「SQLインジェクション」と呼ばれる問題です）。

### コード

`getAllTasks`関数のTODO。

```js
async function getAllTasks() {
  // @@TODO-START id=ch09-1 hint="手順書 9-5 を参考に、SELECTでtasksテーブルの全件を取得しましょう"
  const result = await pool.query('SELECT * FROM tasks ORDER BY id');
  const taskList = [];
  for (const row of result.rows) {
    taskList.push(mapRowToTask(row));
  }
  return taskList;
  // @@TODO-END
}
```

`insertTask`関数のTODO。

```js
async function insertTask(title) {
  // @@TODO-START id=ch09-2 hint="手順書 9-5 を参考に、プレースホルダー（$1）を使ってtasksテーブルに1件追加しましょう"
  const result = await pool.query(
    'INSERT INTO tasks (title) VALUES ($1) RETURNING *',
    [title]
  );
  return mapRowToTask(result.rows[0]);
  // @@TODO-END
}
```

`RETURNING *`を付けると、追加した行の内容をそのまま受け取れます。`mapRowToTask`は、DBの行（`created_at`のようなスネークケース）を、APIで使う形（`createdAt`のようなキャメルケース）に変換する関数で、すでに用意されています。

### うまくいったときの結果

`requests.http`の「タスク一覧を取得する」「タスクを追加する」を送信すると、それぞれ正しく動作する。Neonのダッシュボードでも、追加したタスクが確認できる。

### うまくいかないとき

- 何も返ってこない場合、SQL文の中のテーブル名・列名の綴りを確認する

## 9-8 サーバーを再起動してもデータが残ることを確認する

### やること

第7章では、サーバーを再起動するとデータが消えました。今回はどうなるか確認します。

### 操作

1. `npm run dev`を`Ctrl+C`で止める
2. もう一度`npm run dev`で起動する
3. ブラウザを再読み込みする

### うまくいったときの結果

再起動前に追加したタスクが、消えずに残っている。

### 考えてみよう

第7章の`let tasks = [...]`（ファイル内の配列）と、今回のNeon（データベース）の違いを、自分の言葉で説明してみましょう。「なぜバックエンドを挟むのか」（フロントから直接データベースにつながない理由）も、あわせて隣の人に説明してみてください。

## この章の確認チェック

- サーバーを再起動しても、タスクが残る
- `.env`がGitの管理対象に入っていない（`git status`に出てこない）
- 「なぜバックエンドを挟むのか」を一言で説明できる
