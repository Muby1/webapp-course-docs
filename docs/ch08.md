# 第8章 フロントとバックをつなぐ

## この章のゴール

画面の操作でAPIを呼び出し、開発者ツールのNetworkタブで通信の中身を確認できるようになります。

## 8-1 Networkタブの見方

### やること

ブラウザの開発者ツールには、通信の内容を確認できる「Network」タブがあります。使い方を確認します。

### 操作

1. `http://localhost:3000`を開き、`F12`キーで開発者ツールを開く
2. 「Network」タブを選ぶ
3. ページを再読み込みする（`F5`）

### うまくいったときの結果

一覧が表示され、Networkタブに通信の記録が並ぶ。1つクリックすると、次が確認できる。

- **メソッド**：GETやPOSTなど、どんな種類のお願いか
- **URL**：どこに送ったか
- **ステータス**：200や404など、返事の結果
- **リクエスト/レスポンスの中身**：送った内容・返ってきた内容

［スクショ ch08-1：Networkタブの各項目（メソッド・URL・ステータス・中身）］

## 8-2 画面を開いたときにタスク一覧を取得して表示する

### やること

これまでファイルの中のダミー配列を表示していた部分を、バックエンドのAPIから取得したデータを表示するように書き換えます。`public/script.js`を開いてください。

### コード（写経）

ファイルの上の方が、次のように変わっています。

```js
// APIから取得したタスクの一覧を入れておく
let taskList = [];

// バックエンドからタスクの一覧を取得し、画面に表示する（第8章で説明）
async function loadTasks() {
  const response = await fetch('/api/tasks');
  const data = await response.json();
  taskList = data;
  renderTaskList();
}
```

`fetch`は、指定したURLにリクエストを送るための命令です。サーバーからの返事が返ってくるまで時間がかかることがあるため、`await`を付けて「返事が来るまで待つ」という書き方をします（`async`/`await`はこの講座で使う「時間のかかる処理を待つ」ための書き方です）。返ってきた`response`から、`response.json()`で中身をJavaScriptのデータに変換します。

ファイルの一番下にある`renderTaskList();`という呼び出しを、`loadTasks();`に書き換えてください（ページを開いたときに、ダミー配列ではなくAPIから取得するようにするためです）。

### うまくいったときの結果

ページを開くと、第7章で`requests.http`から追加したタスクを含む、実際のAPIのデータが表示される。Networkタブに、`GET /api/tasks`のリクエストが記録されている。

### うまくいかないとき

- 何も表示されない場合、Networkタブで`GET /api/tasks`のステータスを確認する。`npm run dev`が起動しているか確認する

## 8-3 追加ボタンでPOSTする

### やること

`handleAddClick`関数を、配列に直接追加する形から、APIにPOSTする形に書き換えます。

### コード（写経）

```js
async function handleAddClick() {
  // Content-Typeヘッダーで「JSON形式で送る」と伝え、
  // JSON.stringifyでオブジェクトを送信できる文字列に変換する（第8章で説明）
  const response = await fetch('/api/tasks', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ title: taskTitleInput.value })
  });
  const hasError = await displayErrorIfAny(response);
  if (hasError) {
    return;
  }

  taskTitleInput.value = '';
  await loadTasks();
}
```

`JSON.stringify`は、JavaScriptのオブジェクト（`{ title: ... }`）を、通信で送れる文字列（JSON形式。第3章の3-9を参照）に変換します。`displayErrorIfAny`という関数は8-5で完成させます。今はまだ中身がTODOのままなので、一度置いておいて次に進んでください。

### うまくいったときの結果

（8-5まで終えると）追加ボタンを押すと、Networkタブに`POST /api/tasks`が記録され、一覧に反映される。

## 8-4 完了切り替え・削除もAPIにつなぐ

### やること

`handleToggleClick`・`handleDeleteClick`も、8-3を真似して書き換えます。

### コード（写経）

```js
async function handleToggleClick(event) {
  const taskId = Number(event.target.dataset.taskId);
  const newDone = event.target.checked;
  const response = await fetch('/api/tasks/' + taskId, {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ done: newDone })
  });
  const hasError = await displayErrorIfAny(response);
  if (hasError) {
    return;
  }
  await loadTasks();
}

async function handleDeleteClick(event) {
  const taskId = Number(event.target.dataset.taskId);
  const response = await fetch('/api/tasks/' + taskId, { method: 'DELETE' });
  const hasError = await displayErrorIfAny(response);
  if (hasError) {
    return;
  }
  await loadTasks();
}
```

### うまくいったときの結果

（8-5まで終えると）チェックボックス・削除ボタンの操作が、それぞれNetworkタブに`PUT`・`DELETE`のリクエストとして記録される。

### 補足：1回の操作でリクエストが2つ出る

追加・完了切り替え・削除のどれも、変更のリクエスト（POST/PUT/DELETE）の直後に、一覧を取り直すリクエスト（`loadTasks`の中の`GET`）が呼ばれています。そのため、Networkタブには1回の操作につき2つのリクエストが表示されます。「変更のお願い」と「最新の状態をもらい直すお願い」の2つがある、と考えてください。

## 8-5 空のタイトルで追加し、エラーメッセージを表示する

### やること

`index.html`にはすでに`<p id="errorMessage" class="error-message"></p>`という要素が用意されています。`displayErrorIfAny`関数のTODOを埋め、APIがエラーを返したときにここにメッセージを表示します。

### コード

```js
async function displayErrorIfAny(response) {
  // @@TODO-START id=ch08-1 hint="手順書 8-5 を参考に、response.okがfalseならエラーメッセージを表示してtrueを、そうでなければメッセージを消してfalseを返しましょう"
  if (response.ok === false) {
    const data = await response.json();
    errorMessageElement.textContent = data.error;
    return true;
  }
  errorMessageElement.textContent = '';
  return false;
  // @@TODO-END
}
```

`response.ok`は、ステータスコードが200番台（成功）かどうかを`true`/`false`で教えてくれます。falseのとき（400や404などのとき）は、レスポンスの中身（`{ error: '...' }`）を取り出して画面に表示し、`true`を返します。成功していれば、前に表示されていたメッセージを消して`false`を返します。

この関数は、8-2で書いた`loadTasks`（一覧取得）の中でも実は使われています。`loadTasks`側のコードは、これまでの手順で完成済みのものが用意されています。

### うまくいったときの結果

空のタイトルのまま追加ボタンを押すと、画面に「タイトルは1文字以上100文字以内で入力してください」のようなメッセージが表示される。正しく追加できたときは、メッセージが消える。

### うまくいかないとき

- メッセージが表示されない場合、`errorMessageElement`が正しく取得できているか（`index.html`側の`id="errorMessage"`と一致しているか）を確認する
