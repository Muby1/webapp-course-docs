# よくあるつまずきとその対処

うまくいかないときは、まずこのページで似た症状を探してください。見当たらない場合は、講師・TAに質問してください。

## 事前課題

### GitHubの確認メールが届かない

迷惑メールフォルダを確認してください。それでも届かない場合、別のメールアドレスで登録し直してください。

### Gitのインストール画面で迷ったとき

Git for Windowsのインストーラーには多くの画面が出てきますが、**改行コードの設定（Configuring the line ending conversions）以外は、基本的にすべて既定（最初から選ばれているもの）のまま「Next」を押して進めて問題ありません**。

### Node.jsのバージョンが違う

すでに別のバージョンのNode.jsが入っている場合は、Windowsの「アプリと機能」から一度アンインストールしてから、指定されたバージョンを入れ直してください。

### 'node'や'git'が認識されないと言われる

「'node' は、内部コマンドまたは外部コマンド...として認識されていません」のようなメッセージが出る場合、インストール直後でVS Codeやターミナルが古い設定のままになっていることが原因です。VS Codeを再起動しても直らない場合は、パソコン自体を再起動してください。

## 第2章 はじめてのHTML

### 拡張子が表示されない

エクスプローラーの「表示」メニューの中に「ファイル名拡張子」の項目が見当たらない場合、Windowsのバージョンによってメニューの位置が異なります。「（自分のWindowsのバージョン） ファイル名拡張子 表示」で検索してください。

### 作業フォルダの場所を間違えた

日本語・空白・OneDriveを含む場所に作業フォルダを作ってしまった場合、`C:\dev`のようなシンプルな場所に作り直し、ファイルを移動してください。

### index.html.txtになっている

ファイル名が`index.html.txt`のように、拡張子が二重になっていないか確認してください。2-1で拡張子を表示する設定にしたうえで、ファイル名を`index.html`に変更してください。

### 保存したのに変わらない

ブラウザは自動では再読み込みされません。ファイルを保存したあと、ブラウザの画面で`F5`キー（再読み込み）を押してください。

### HTMLの表示が崩れる

閉じタグ（`</li>`など）の書き忘れ、`<`と`>`の打ち間違いがないか確認してください。VS Codeでは、タグの対応が取れていない場合に色がおかしくなることがあります。

## 第3章 JavaScript基礎

### consoleに何も表示されない

`<script>`タグの位置（`</body>`の前にあるか）、`console.log`の綴り（大文字・小文字、括弧の対応）を確認してください。開発者ツールで正しく「Console」タブを開けているかも確認してください。

### =と===を間違えた

`=`は「代入」（値を入れる）、`===`は「比較」（等しいかどうかを調べる）です。`if (age = 20)`のように書くと、意図せず代入が実行されてしまいます。条件分岐の中では`===`を使ってください。

### 関数の戻り値がundefinedになる

関数の中で`return`を書き忘れていないか確認してください。`return`が無い関数は、何も呼び出し元に返しません。

### おみくじがいつも同じ結果になる

`Math.floor(Math.random() * 配列の長さ)`の「配列の長さ」の部分が、正しい配列の`.length`になっているか確認してください。固定の数字を書いてしまっていないか確認してください。

### ボタンを押しても反応しない

`document.getElementById('...')`のカッコの中の文字列と、HTML側の`id="..."`の文字列が完全に一致しているか確認してください（大文字・小文字も区別されます）。

## 第5章 開発環境の確認とGit入門

### core.autocrlfがNGになる

ターミナルで次を実行してください。

```
git config --global core.autocrlf true
```

**すでにクローン済みのフォルダがある場合**は、設定を直したあとに、そのフォルダを一度削除してクローンし直してください（個別のファイルだけ直す方法は扱いません）。

### コミット時にvimが開いて抜けられない

`git commit`のときに`-m "メッセージ"`を付け忘れると、メッセージ入力用の画面（vim）が開いてしまいます。抜けるには、`Esc`キーを押してから`:q`と入力し、Enterキーを押してください。次からは`-m`を忘れないようにしてください。

## 第7章 バックエンド：APIを作る

### ポートが使用中と言われる

前回起動した`npm run dev`が完全に終了していない可能性があります。ターミナルを一度すべて閉じてから、VS Codeを再起動してもう一度試してください。

**`Ctrl+C`で止めたはずなのに再発する場合**：`npm run dev`は、ファイルの変更を監視して裏側のプログラムを作り直す仕組み（`--watch`）を使っており、`Ctrl+C`で見えている画面だけが終了し、実際にポートを使っているプログラムが残ってしまうことがあります。PowerShellで次を実行し、該当するプログラムを終了させてください。

```
netstat -ano | findstr :3000
taskkill /PID 表示された番号 /F
```

それでも直らない場合は、ターミナルのタブやウィンドウ自体を閉じて開き直してください。

### TODOを埋めたのに反応が変わらない

保存を忘れていないか確認してください（VS Codeのタブに●印が出ていないか）。`npm run dev`はファイルの変更を検知して自動的に再起動しますが、再起動のログがターミナルに出ているかも確認してください。
