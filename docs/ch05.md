# 第5章 開発環境の確認とGit入門

## この章のゴール

開発に必要なツールが揃っていることを確認し、Gitでコミットと「壊して戻す」ができるようになります。

## 5-1 環境チェックスクリプトを作成・実行する

### やること

ここまでの事前課題・準備が正しくできているかを、まとめて確認するスクリプトを実行します。中身をすべて理解する必要はありません（完成済みのコードとして提供します）。

### コード

`C:\dev`の中に`check.js`という名前でファイルを作り、次の内容をそのまま貼り付けて保存する。

```js
// 開発に必要なものが揃っているかを確認するスクリプト（第5章で使用）。
// 手順書のとおりに保存し、node check.js で実行する
// （完成済みのコードとして提供。中身を理解する必要はない）
const { execSync } = require('child_process');

const REQUIRED_NODE_MAJOR_VERSION = 24;

function runCommand(command) {
  try {
    const output = execSync(command, { encoding: 'utf8' });
    return { success: true, output: output.trim() };
  } catch (error) {
    return { success: false, output: '' };
  }
}

function containsSpace(text) {
  return text.indexOf(' ') !== -1;
}

function containsOneDrive(text) {
  return text.indexOf('OneDrive') !== -1;
}

function containsJapaneseCharacter(text) {
  for (let i = 0; i < text.length; i = i + 1) {
    const code = text.charCodeAt(i);
    const isHiragana = code >= 0x3040 && code <= 0x309F;
    const isKatakana = code >= 0x30A0 && code <= 0x30FF;
    const isKanji = code >= 0x4E00 && code <= 0x9FFF;
    if (isHiragana || isKatakana || isKanji) {
      return true;
    }
  }
  return false;
}

function checkNodeVersion() {
  const versionText = process.version;
  const majorVersionText = versionText.split('.')[0].replace('v', '');
  const majorVersion = Number(majorVersionText);
  if (majorVersion === REQUIRED_NODE_MAJOR_VERSION) {
    return { name: 'Node.js（' + versionText + '）', ok: true };
  }
  return {
    name: 'Node.js（' + versionText + '）',
    ok: false,
    message: 'バージョン' + REQUIRED_NODE_MAJOR_VERSION + '系が必要です。事前課題の手順を見てインストールし直してください'
  };
}

function checkNpm() {
  const result = runCommand('npm -v');
  if (result.success) {
    return { name: 'npm（' + result.output + '）', ok: true };
  }
  return { name: 'npm', ok: false, message: 'npmが実行できません。事前課題を見てNode.jsを入れ直してください' };
}

function checkGit() {
  const result = runCommand('git --version');
  if (result.success) {
    return { name: 'Git（' + result.output + '）', ok: true };
  }
  return { name: 'Git', ok: false, message: 'Gitが実行できません。事前課題を見てGit for Windowsを入れ直してください' };
}

function checkGitUserName() {
  const result = runCommand('git config --global user.name');
  if (result.success && result.output !== '') {
    return { name: 'Gitのユーザー名（' + result.output + '）', ok: true };
  }
  return {
    name: 'Gitのユーザー名',
    ok: false,
    message: '設定されていません。「git config --global user.name "名前"」を実行してください'
  };
}

function checkGitUserEmail() {
  const result = runCommand('git config --global user.email');
  if (result.success && result.output !== '') {
    return { name: 'Gitのメールアドレス（' + result.output + '）', ok: true };
  }
  return {
    name: 'Gitのメールアドレス',
    ok: false,
    message: '設定されていません。「git config --global user.email "メールアドレス"」を実行してください'
  };
}

function checkGitAutocrlf() {
  const result = runCommand('git config --global core.autocrlf');
  if (result.success && result.output === 'true') {
    return { name: 'core.autocrlf（true）', ok: true };
  }
  return {
    name: 'core.autocrlf',
    ok: false,
    message: '「git config --global core.autocrlf true」を実行してください'
  };
}

function checkWorkingDirectoryPath() {
  const currentPath = process.cwd();
  if (containsJapaneseCharacter(currentPath)) {
    return { name: '作業フォルダのパス', ok: false, message: '日本語が含まれています：' + currentPath };
  }
  if (containsSpace(currentPath)) {
    return { name: '作業フォルダのパス', ok: false, message: '空白が含まれています：' + currentPath };
  }
  if (containsOneDrive(currentPath)) {
    return { name: '作業フォルダのパス', ok: false, message: 'OneDrive内のフォルダです：' + currentPath };
  }
  return { name: '作業フォルダのパス（' + currentPath + '）', ok: true };
}

function checkNetworkConnection(hostName) {
  // pingは社内ネットワークで遮断されていることがあるため、実際に使う通信と
  // 同じHTTPS（curl.exe、Windows 10/11に標準で入っている）で確認する
  const result = runCommand('curl.exe -s -o NUL --max-time 5 https://' + hostName);
  if (result.success) {
    return { name: 'ネットワーク（' + hostName + '）', ok: true };
  }
  return {
    name: 'ネットワーク（' + hostName + '）',
    ok: false,
    message: hostName + 'に接続できません。社内ネットワークやVPNの設定を確認してください'
  };
}

function main() {
  const results = [];
  results.push(checkNodeVersion());
  results.push(checkNpm());
  results.push(checkGit());
  results.push(checkGitUserName());
  results.push(checkGitUserEmail());
  results.push(checkGitAutocrlf());
  results.push(checkWorkingDirectoryPath());
  results.push(checkNetworkConnection('github.com'));
  results.push(checkNetworkConnection('registry.npmjs.org'));

  console.log('=== 確認結果 ===');
  let hasNg = false;
  for (const result of results) {
    const statusText = result.ok ? 'OK' : 'NG';
    console.log(statusText + '  ' + result.name);
    if (result.ok === false) {
      hasNg = true;
      console.log('      → ' + result.message);
    }
  }
  console.log('');
  if (hasNg) {
    console.log('NGの項目があります。上のメッセージを見て直してください。');
  } else {
    console.log('すべてOKです。');
  }
}

main();
```

ターミナルで次を実行する。

```
node check.js
```

### うまくいったときの結果

9項目すべて`OK`と表示される。

［スクショ ch05-1：環境チェックスクリプトの実行結果（全項目OK）］

### うまくいかないとき

- `core.autocrlf`が`NG`の場合、表示されたコマンド（`git config --global core.autocrlf true`）を実行してからもう一度`node check.js`を実行する → `faq.md`の「core.autocrlfがNGになる」を見る
- 作業フォルダのパスが`NG`の場合、2-2で作った`C:\dev`のようなフォルダに移動してから実行する
- ネットワークの項目が`NG`の場合、会社や学校のネットワークの制限を確認する（自宅などの別のネットワークで試す、講師に相談する）

## 5-2 Gitの初期設定を確認する

### やること

前の手順ですでに設定できているはずですが、改めて確認します。

### コマンド

```
git config --global user.name
git config --global user.email
git config --global init.defaultBranch
```

### うまくいったときの結果

1つ目は自分の名前、2つ目はメールアドレスが表示される。3つ目が`main`になっていない場合は、次を実行する。

```
git config --global init.defaultBranch main
```

### うまくいかないとき

- 何も表示されない場合、5-1の`check.js`のメッセージのとおりに`user.name`・`user.email`を設定する

## 5-3 自己紹介ページのフォルダで`git init`する

### やること

第2章で作った`C:\dev\my-profile`フォルダを、Gitで管理を始めます。「リポジトリ」は、Gitが変更履歴を記録する単位のことです。

### コマンド

```
cd C:\dev\my-profile
git init
```

### うまくいったときの結果

「Initialized empty Git repository in ...」のようなメッセージが表示される。フォルダの中に（隠しフォルダの）`.git`ができる。

### うまくいかないとき

- 別のフォルダで実行してしまった場合、`cd`で正しいフォルダに移動してからやり直す

## 5-4 コミットを繰り返す

### やること

ファイルの変更を、Gitの記録（コミット）として残します。「ステージング」は、次のコミットに含める変更を選ぶ作業、「作業ツリー」は今編集しているファイルそのものを指します。

### コマンド

`index.html`を少し書き換えて保存したあと、次を実行する。

```
git status
git add .
git commit -m "見出しの文言を変える"
```

これを、内容を変えながら3回以上繰り返す。

### うまくいったときの結果

- `git status`で、変更されたファイルが赤字（ステージング前）→ `git add .`のあとは緑字（ステージング後）で表示される
- `git commit`のあとは、`git status`が「nothing to commit, working tree clean」になる

### うまくいかないとき

- コミット時にエディタ（`vim`という画面）が開いて操作方法が分からなくなった場合、`-m "メッセージ"`を付け忘れていないか確認する。開いてしまった場合は`Esc`キーを押してから`:q`と入力してEnterを押すと抜けられる → `faq.md`の「コミット時にvimが開いて抜けられない」を見る
- `git add .`を忘れて`git commit`すると、何も記録されない

## 5-5 `git log`で履歴を見る

### やること

これまでのコミットの履歴を確認します。

### コマンド

```
git log
```

### うまくいったときの結果

今まで作ったコミットが、新しいものから順に一覧表示される。コミットメッセージが自分の付けたとおりに並んでいる。

［スクショ ch05-3：git logの履歴表示（コミットが3件以上並んだ状態）］

### うまくいかないとき

- 一覧の表示から抜けられない場合、`q`キーを押す

---

## 5-6 ファイルを壊して`git restore`で戻す

### やること

わざとファイルを壊して保存し、直前のコミットの状態に戻せることを確認します。

### コマンド

`index.html`の内容を大きく削除するなどして保存したあと、次を実行する。

```
git status
git restore index.html
```

### うまくいったときの結果

`git restore`を実行すると、ファイルの内容が直前のコミット時点に戻る（保存し直さなくても、開いているエディタの表示も戻る）。

### 考えてみよう

コミットをしていなかったら、この操作で元に戻せたでしょうか。こまめにコミットしておくことの意味を、隣の人と話してみてください。

## 5-7 VS Codeの「ソース管理」画面を確認する

### やること

ここまでターミナルで行ってきた操作が、VS Codeの画面からも同じようにできることを確認します。

### 操作

1. `index.html`をまた少し書き換えて保存する
2. VS Code左側の、枝分かれしたようなアイコン（ソース管理）をクリックする
3. 変更されたファイルの一覧が表示されることを確認する
4. メッセージを入力し、青いチェックマーク（コミット）ボタンを押す

### うまくいったときの結果

ターミナルで`git log`を実行すると、今VS Code上で行ったコミットが履歴に追加されている。
