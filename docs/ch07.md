# 第7章 バックエンド：APIを作る

## この章のゴール

Expressというソフトを使ってタスクのAPI（一覧取得・追加）を作り、REST Clientという拡張機能で動作を確認できるようになります。

## 7-1 `npm install`を実行する

### やること

このプロジェクトが必要としているソフト（ライブラリ）を、まとめてインストールします。

### コマンド

VS Codeでこのプロジェクトのフォルダを開き、ターミナルで次を実行する。

```
npm install
```

### うまくいったときの結果

`node_modules`というフォルダが作られる。VS Codeの「ソース管理」画面や`git status`を確認すると、`node_modules`はGitの管理対象外（変更として表示されない）になっている。これは`.gitignore`にあらかじめ書かれているためです。

### うまくいかないとき

- 「'npm' は、内部コマンドまたは外部コマンド...として認識されていません」と出る場合、事前課題のNode.jsのインストールができているか確認する → `faq.md`の「'node'や'git'が認識されないと言われる」を見る

---

## 7-2 サーバーを起動する

### やること

`npm run dev`でサーバーを起動し、ブラウザから`/health`というURLにアクセスしてみます。

### コマンド

```
npm run dev
```

### うまくいったときの結果

ターミナルに何かメッセージが表示され、コマンドが終了せずに動き続ける状態になる。ブラウザで `http://localhost:3000/health` を開くと、次のように表示される。

```json
{"status":"ok"}
```

### うまくいかないとき

- 「ポートが使用中です」というエラーが出る場合、前回起動したサーバーが終了しきっていない可能性がある → `faq.md`の「ポートが使用中と言われる」を見る

---

## 7-3 REST Clientで動作確認する

### やること

REST ClientというVS Codeの拡張機能を使うと、`requests.http`というファイルにAPIへのリクエストを書いて、ボタン1つで送信できます。まず`/health`宛てに送ってみます。

### 操作

1. VS Codeの拡張機能タブから「REST Client」を検索してインストールする
2. プロジェクトの`requests.http`ファイルを開く
3. 一番上の`GET http://localhost:3000/health`という行の上に表示される「Send Request」をクリックする

### うまくいったときの結果

右側に新しいタブが開き、レスポンス（`{"status":"ok"}`など）が表示される。

［スクショ ch07-2：REST Clientでのリクエスト結果］

`requests.http`のPOST・PUTのリクエストには`Content-Type: application/json`という行があります。これは「ヘッダー」と呼ばれる、リクエストに付ける荷札のような情報です。「これから送る内容はJSON形式です」とサーバーに伝えるために付けます。

### うまくいかないとき

- 「Send Request」が表示されない場合、拡張機能が正しくインストールされているか確認する

## 7-4 GET `/api/tasks` を完成させる

### やること

`src/app.js`を開くと、`getTasks`という関数の中に、次のような印が付いた部分があります。

```js
async function getTasks(req, res) {
  try {
    // @@TODO-START id=ch07-1 hint="手順書 7-4 を参考に、tasks配列をJSONで返しましょう"

    // @@TODO-END
  } catch (error) {
    console.error(error);
    res.status(500).json({ error: 'サーバーでエラーが発生しました' });
  }
}
```

この`@@TODO-START`と`@@TODO-END`の間に、自分でコードを書きます。すぐ上のファイル冒頭に`let tasks = [...]`という配列があるので、これをそのままレスポンスとして返しましょう。JSON形式で返すには`res.json()`を使います。

`function`の前に付いている`async`という文字が気になった人もいるかもしれません。サーバーの処理は時間がかかることがあるので、この講座ではこの書き方をします。詳しくは第8章で説明するので、今はそのままにしておいてください。

### コード

`@@TODO-START`と`@@TODO-END`の間に、次の1行を書く。

```js
res.json(tasks);
```

### うまくいったときの結果

`requests.http`の「タスク一覧を取得する」を送信すると、次のように配列が返ってくる。

```json
[
  { "id": 1, "title": "牛乳を買う", "done": false, "createdAt": "2026-01-01" },
  { "id": 2, "title": "掃除をする", "done": true, "createdAt": "2026-01-01" }
]
```

### うまくいかないとき

- 何も返らない、または`undefined`と表示される場合、`res.json(tasks)`の`tasks`の綴りを確認する → `faq.md`の「TODOを埋めたのに反応が変わらない」を見る

## 7-5 POST `/api/tasks` を完成させる

### やること

タスクを新しく追加するAPIには、2つのTODOがあります。1つ目はタイトルのチェック、2つ目はタスクの作成と登録です。

`src/app.js`の`createTask`関数を見ると、タイトルが文字列かどうかのチェックの後に、次の部分があります。

```js
// @@TODO-START id=ch07-2 hint="手順書 7-5 を参考に、前後の空白を取り除いてから文字数を確認しましょう"

// @@TODO-END
```

タイトルの前後の空白を取り除き（第3章の`.trim()`）、空文字や100文字を超える場合は400エラーにします。

### コード（1つ目のTODO）

```js
const title = req.body.title.trim();
if (title === '' || title.length > 100) {
  res.status(400).json({ error: 'タイトルは1文字以上100文字以内で入力してください' });
  return;
}
```

続けて、次の部分があります。

```js
// @@TODO-START id=ch07-3 hint="手順書 7-5 を参考に、buildTask関数で新しいタスクを作り、tasks配列に追加して201で返しましょう"

// @@TODO-END
```

`buildTask(title)`という関数が、すぐ上にすでに用意されています。この関数にタイトルを渡すと、新しいタスクのオブジェクトを作ってくれます。それを`tasks`配列に追加し、201というステータスコードとともに返します。

### コード（2つ目のTODO）

```js
const newTask = buildTask(title);
tasks.push(newTask);
res.status(201).json(newTask);
```

### うまくいったときの結果

`requests.http`の「タスクを追加する」を送信すると、`201`のステータスコードとともに、新しく作られたタスクが返ってくる。「空のタイトルで追加する」を送信すると`400`が返ってくる。

### うまくいかないとき

- `newTask`が`undefined`になる場合、`buildTask`関数に`title`を渡し忘れていないか確認する
- 400になるはずが201になってしまう場合、1つ目のTODOのチェックが先に実行されているか（コードの順番）を確認する → `faq.md`の「TODOを埋めたのに反応が変わらない」を見る

## 7-6 PUTとDELETEを読んで動作確認する

### やること

完了状態の更新（PUT）と削除（DELETE）は、すでに完成したコードが書かれています。読んで、何をしているか確認しましょう（自分で書く部分はありません）。

### 確認すること

1. `src/app.js`の`updateTask`関数と`deleteTask`関数を読む
2. `requests.http`を使って、存在しないid（例：`999999`）にPUT・DELETEを送り、`404`が返ってくることを確認する

### うまくいったときの結果

存在しないidを指定すると、どちらも次のように404が返る。

```json
{"error":"タスクが見つかりません"}
```

## 7-8 サーバーを再起動してデータが消えることを確認する

### やること

`requests.http`でタスクを追加した後、サーバーを再起動して、追加したタスクが消えることを確認します。

### 操作

1. `requests.http`でタスクを1件追加する
2. `npm run dev`を実行しているターミナルで`Ctrl+C`を押し、サーバーを停止する
3. もう一度`npm run dev`で起動する
4. 「タスク一覧を取得する」を送信する

### うまくいったときの結果

先ほど追加したタスクが消えており、最初の2件（牛乳を買う・掃除をする）だけが返ってくる。

### 考えてみよう

なぜ再起動するとデータが消えたのでしょうか。今、タスクはどこに保存されているでしょうか（`src/app.js`の`let tasks = [...]`を見て確認してください）。この問題は第9章で解決します。
